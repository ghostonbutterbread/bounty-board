# Bounty Board backend contract

## Run and security boundary

`python3 app.py [--root /absolute/path/to/Shared] [--port 9001]` uses only the Python standard library. The root is the **parent** containing `web_bounty/` and/or `binaries/`; it defaults to `~/Shared`. It binds IPv4 `127.0.0.1` only; there is no remote-listen option, authentication, TLS, CORS or remote-exposure support. Do not expose it with a proxy or tunnel. Other local processes can access it. API output can contain sensitive program names, findings, report text, URLs and evidence references; do not publish or log it. Responses are `Cache-Control: no-store`; requests are not logged by the server. The server accepts only `Host: 127.0.0.1:<port>` or `localhost:<port>`; when present `Origin` must equal the exact HTTP host, and cross-site Fetch Metadata requests are refused. This is defense in depth, not authentication against local processes.

The server serves `static/index.html` at `/`, and other files under `static/` at their corresponding URL paths. Filesystem paths, including symlinks, are not exposed through this static route. The HTTP server operates against live sources, not a globally atomic portfolio snapshot. Refresh to see external changes.

## `GET /api/data`

JSON shape (all collections are lane-scoped):

```json
{"programs":[{"id":"web_bounty/example","name":"example","family":"web_bounty","lanes":[{"name":"web","findings":[],"coverage":{"counts":{},"items":[],"total":0,"mapped_kinds":{},"unclassified_surfaces":0},"map":[],"gadgets":[],"reports":[],"warnings":[]}]}],"warnings":[]}
```

This is a structural example only, not a claim that an empty or missing source is complete. Discovery accepts `web_bounty/{program}/{web|api}` and `binaries/{program}/{apk|exe|mac}`, skips underscore-prefixed program housekeeping and symlinked family/program/lane directories. Program ID is `family/name`; lane name is the directory name. Other directories are not inferred to be programs/lanes.

* `findings`: list from `ledgers/ledger.json` `findings`, or `null` if missing, malformed, unreadable, or over 5 MB. Each object selects `fid`, `type`, `title`, `class_name`, `severity`, `status`, `review_tier`, `submission`, `submission_status`, `platform_outcome`, `file`; absent values are `null`, except that `title` falls back to the recorded `type`. The BBH submission object, where present, has distinct `state`, `result`, and optional `report`; do not infer submission or duplicate outcome from finding status, severity, a draft, or file names. Ledger fields are displayed as recorded, not normalized or validated by the write-owning API. No inline update is available.
* `coverage`: live `ledgers/surface_coverage.sqlite`, or `null` on missing/unavailable/unsupported DB. `items` contains joined surface/class assessments: `surface_id`, `kind`, `host`, `surface_key`, `input_key`, `consumer`, `fingerprint`, `run_id`, `class_name`, `status`, `pressure`, `reason`, `boundary`, `axes`, `evidence_refs`, `reopen_when`, `assessed_fingerprint`, and `prior_status` when stale. The BBH legacy `untested` and `exhausted` statuses are shown as `no_assessment` and `bounded_review`; fingerprint/run mismatches become `stale`. `counts` count these questions, `total` is their sum, `mapped_kinds` counts mapped surfaces, and `unclassified_surfaces` counts mapped surfaces with no assessment question. Missing/empty coverage is not evidence of exhaustive mapping. SQLite opens with `mode=ro`, **not** `immutable`, so committed WAL transactions remain visible; SQLite's normal read-only WAL shared-memory coordination applies. The static source-file `coverage.json` is intentionally not conflated with live coverage.
* `map`: list from `recon/maps/map.jsonl`, with `title`, `url`, `surface`, `scope`, `status`, `path`, `tags`, `timestamp`; `null` means missing/invalid/unavailable or over 5 MB. `gadgets` is the subset whose tags contain `gadget`, including residual and archived observations; it is not a list of confirmed exploits. MapStore application-behavior indexes and observation bodies are not currently loaded.
* `reports`: list of `{path, name}` for Markdown files recursively under `reports/`, with `path` relative to that directory. Symlink files and directories are skipped. `null` means the directory is missing or unusable; warnings signal a partial directory traversal. Content is loaded separately.
* `warnings`: strings describing missing or unavailable sources. Top-level `root_unavailable` and `discovery_incomplete` distinguish an unavailable/partially read tree from an authoritative empty portfolio. Lane warnings include `ledger_missing`, `map_missing`, `coverage_missing`, `reports_missing`, and corresponding `*_unavailable_or_invalid`. `null` means unknown/unavailable, never zero.

No `capabilities` are advertised: finding metadata, coverage, MapStore and report edits are disabled. The API does not update generated ledger files or invoke BBH write commands. No independent record store, fabricated metrics, submission inference, search indexing, or current-agent activity is provided.

## `GET /api/report?family=web_bounty&program=example&lane=web&path=raw%2Fexample.md`

On success: JSON `{ "content": "<UTF-8 Markdown>", "revision": "<sha256 hex of exact file bytes>", "editable": false }` and HTTP `ETag: "<same sha256 hex>"`. Treat revision as opaque. The path is relative to the selected lane's `reports/`, must name an existing `.md` file, and all components are opened without following symlinks. Traversal, absolute paths, symlinks, malformed/non-UTF-8/oversized files, and unavailable paths return `404 {"error":"report_not_found_or_unavailable"}`. Bytes are limited to 5 MB. Refresh this endpoint to observe an external edit; revisions are content hashes, not locks.

All `PUT`, `PATCH`, `POST` and `DELETE` requests return `403 {"error":"editing_disabled","message":"Report writes are disabled; retain your draft."}`. This applies to matching and stale revisions alike; there is currently **no** conflict-checking write endpoint, no server-side autosave, and no claim of `409` conflict detection. Preserve drafts client-side and visibly label them unsaved. A revision check followed by atomic rename is not a compare-and-swap: an uncoordinated BBH/editor/sync writer can change the file in between. Safe autosave requires a proven shared lock/versioned compare-and-swap protocol followed by every actual writer, or another owner-provided atomic conditional-write API. A lock used only by this server would not meet that requirement.

## Limitations

The data directory is assumed trusted against hostile local processes actively replacing directories or SQLite/WAL paths concurrently. Ordinary symlinks are refused, and report content opens use component-wise `O_NOFOLLOW`; SQLite's pathname open cannot guarantee containment against an adversarial concurrent filesystem swap. Do not point this server at a tree writable by untrusted users. Non-SQLite source reads are bounded at 5 MB; SQLite rows and report listing are not paginated. Unexpected/incompatible schemas return unknown and warnings rather than invented records. Coverage writes, report edits, finding metadata edits, MapStore body retrieval and static-source coverage are deferred.
