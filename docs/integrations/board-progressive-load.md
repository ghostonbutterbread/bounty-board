## Implemented contract

Ordinary `GET /api/data` remains a full synchronous scan. Initial browser requests explicitly opt into a summary using `X-Bounty-Board-Phase: summary`; `?phase=summary` is also accepted. A server with any configured metadata writer, collaboration store, source autosave, or fixture publisher ignores the opt-in and returns the ordinary full response. Missing roots also retain the existing full-response semantics. A valid read-only summary uses normal ledger/map/coverage discovery, but does not index reports; each lane has `reports: null`, the response has `reports_loading: true`, `capabilities.source_authoritative: false`, and no writable capabilities. The UI labels reports Loading, blocks report actions, and starts exactly one full request for the summary; no workers, queues, background caches, or automatic polling were added.

For phased reads, canonical root path, device and inode are checked before and after discovery and bound in an opaque `root_instance`. The full request must present the same token; a root change returns 409. The browser accepts completion only for its current summary, generation, root identity and root instance, and rechecks the root instance before applying. Manual Refresh invalidates the old generation and follows the pre-existing full request path. A focused in-app control or unsaved draft defers replacement with a visible Apply button; before applying, root is checked again. On failure or changed source, the summary remains and Refresh retries. A missing identity on an otherwise partial response falls back to the existing full path to preserve unscoped draft handling.

**Limits:** these checks detect root replacement at observed points, not an atomic filesystem snapshot, same-inode internal changes, an ABA swap, or changes after the last identity check. Full discovery and existing report endpoints remain live reads. A cold summary can still block on ledger/map/coverage. Each browser can have the one original full read plus a user-requested refresh in flight; there is no process-wide server reader limit or cancellation of blocked filesystem I/O. Legacy full/write-enabled behavior and its pre-existing concurrency limitations are unchanged. An explicit Apply can rerender after the user chooses it; focused controls are otherwise not rerendered by phase completion. No production speed or worst-case latency was measured.
