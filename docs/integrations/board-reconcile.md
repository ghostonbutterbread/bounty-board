## Contract

The collaboration GET includes the currently observed `source_snapshot`. Explicit reconcile POST binds the expected shared revision, exact shared content, exact source snapshot and new request ID into the durable request receipt; it refuses stale source/head, unresolved conflicts and incomplete/uncertain scans. It uses the existing publication operation and never exchanges twice on an exact retry. A source collision can occur after exchange; retain both outcomes and inspect history. The UI previews both copies, confirms publication separately, rejects stale preview and separates store-only saves from Markdown saves. Conflict resolutions are stored first, then the merged result can be explicitly published. A completed multi-request retained scan may authorize one explicit reconciliation if no operation was added; it is still a time-separated best-effort observation. Normal polls scan again and can discover later old-descriptor writes.
