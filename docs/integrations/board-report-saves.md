## Intent and implementation

Build controlled, opt-in real Markdown publication while retaining observable competing versions. This checkpoint implements **only an unconnected SQLite observation primitive**, `CollaborationStore.observe_retained`, and report-scoped event provenance lookup. It does not read, exchange, watch or publish a source file, expose new HTTP APIs, or update the UI. Real source publication remains unavailable; the existing separately guarded fixture publisher is unchanged and was not enabled. No source-identity, filesystem, service, security configuration, remote, Shared or Syncthing changes were made.

The caller supplies a bound operation, original base, observed bytes decoded to text, and a durable observation request ID. A transaction stores an event, content version, event provenance and exact-retry receipt. An observed nonconflicting revision is merged via the existing store merge; conflicting content is retained as an unresolved `retained:conflict` event. The merge base advances only after nonconflicting observations. Reusing a request ID with different content is rejected. Consecutive identical snapshots share an event but record distinct receipts; retries return the historical result, **not** confirmation of the current document or source state. The caller must validate operation and source identities, serialize snapshots in observation order, provide stable IDs, and reconcile the current head separately. This primitive does not guarantee a stable inode read or capture edits between observations. New receipts and versions consume bounded SQLite capacity; journal and other files are not covered by its SQLite page limit. No pruning policy exists.
