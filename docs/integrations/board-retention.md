- **Intent:** prevent silent unbounded normal publication growth without automatically deleting retained versions. One process-local directory-entry count cache is invalidated by directory identity/metadata changes; publication is serialized by the existing store observation lock. Existing entries, including interrupted attempts and symlinks, consume capacity. A statvfs preflight additionally checks free space before creation. Defaults: 1,000 entries, 1 GiB floor, plus 2× draft bytes + 1 MiB estimated headroom. Flags and operator handling are in README and BACKEND_API.
- **Recovery contract:** `capacity` is durably recorded only after no operation/exchange occurred, alongside a source digest. Shared draft stays committed. An exact retry can exchange only after rechecking source, shared head, conflicts, and reconciliation; pending/uncertain operations remain uncertain. The UI retains the exact request, states Markdown was not saved, and offers retry.
- **Limits:** count + free-space preflight is not a byte/disk quota or allocation reservation. Other writers, filesystem overhead, and old descriptors can grow retained inodes after the check. SQLite limit does not cover ancillary files. No automatic cleanup; preserve the whole store together. Lock and cache assume a coherent local filesystem and cooperating users of the same private store; independent sync replicas and hostile private-directory mutations are not coordinated. Retention-path rechecks are point-in-time, not CAS. Actual sync, production filesystem, crash/power-loss and disk-full semantics remain unverified; external writers must be stopped for any considered activation.
