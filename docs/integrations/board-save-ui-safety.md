## Contract

- A successful store-only merged acknowledgment with later local typing advances the causal base to the receipt's **incoming revision**, not its merged head; the backend performs the next three-way merge. An unchanged editor can apply the merged receipt. Inspection of an actual `not_published` store-only receipt follows the same path. Unknown publication outcomes and missing causal information retain the original request and local draft. A publication-only conflict uses the editor's causal base instead of blindly submitting against a polled head; actual store conflicts require explicit review and resolution.
- `editable:false` makes a collaborative report read-only, hides editing and publication controls, prevents scheduled saves/polls and retains local text for copying. With collaboration disabled, browser-only local drafts remain available. This is a UI control; backend enforcement is separately required. Reload and local-storage failures retain the existing warnings/recovery boundaries.
