## Contract and implementation

Read-only summary enumerates program/lane directories without reading ledgers, maps, coverage databases, or reports; unscanned collections are null, not zero. A root-instance-bound `/api/lane` reads one selected lane's ledger, map and coverage. The complete portfolio scan stays bounded to one per server; lane reads, including the selected report index, share an eight-read bound. Legacy unphased full and writer/collaboration paths remain in place.

The selected lane's Reports view now requests `/api/lane-reports` independently of the complete scan. It rereads that lane's owner ledger and uses the existing report classifier, preserving owner IDs, generated-navigation classification, and non-writable flags. The selected index and its report body use a root-instance token, with server checks before and after reads and client checks before rendering. Selectors are constrained to the selected family/program/lane. The browser can open and edit a local draft while a stale complete scan remains held. A busy full scan offers an explicit retry action and retains the draft; the portfolio button's loading state is now scoped to the active snapshot.

Selected-lane responses are kept outside the displayed snapshot until application; every deferred apply rechecks root instance, selection/load/apply generations and intervening view changes. A stale selected result cannot replace a newer complete snapshot; A→B→A invalidates an earlier selected apply. Full results retain their existing focus/draft-aware deferred apply. Checks are observations, not an atomic filesystem lock: a root may change after any identity check.
