## Contract and boundaries

- The report has an explicit Find saved drafts action. It lists matching root/program/lane/report namespaces and offers copyable text and pending-request JSON. Recovery copies rather than deletes the original. It checks the snapshot, refuses to replace an unsaved destination, and holds the source Web Lock while copying. Locked namespaces carry a persistent marker; old unmarked and lockless namespaces are copy-only, because lack of a lock cannot establish that an old browser is inactive. Lockless browsers are also copy-only. The marker establishes that the namespace was created by the new cooperating frontend, not a cross-origin security boundary. Browser storage remains plaintext and can be lost or unavailable.
- Once older history is open, disjoint recent pages produce a queued cursor gap. One bounded history page is fetched per poll until it reaches the old boundary; the UI says history is incomplete while bridging and a failed request leaves the cursor for retry. The browser still retains paged metadata in memory: **the existing session cache can grow without a hard bound**, including during repeated automatic bridging. The 100-event test validates that case, not an unbounded burst, bounded total memory, or arbitrary sustained arrival rates. Design and test a bounded sliding-window cache with clear gap/cursor semantics before claiming a hard memory bound.
- Old conflict actions are disabled when the observed resolution generation changes; the user can refresh that conflict using a bounded history request. As with polling generally, a remote resolution between the last observation and a click can still be rejected by the server; local draft preservation and stale-resolution recovery remain necessary. A resolution followed by a new conflict is detected through resolution events or a missing recent interval, not only the unresolved count.
- Existing history preview and undo code were left intact. Source publication remains experimental and unsafe for real reports; no backend or publishing safety work is implied.
- Recovery now verifies the destination write by reading the exact serialized value back before declaring success. On quota, storage exception, changed snapshot, or readback mismatch it retains the original orphan, displays the current editor text in the copy/download recovery panel, and blocks shared scheduling. A save also verifies its exact pending payload before any POST. Conflict recovery immediately updates the editor, preview, conflict message and available history actions. Snapshot checks are not an atomic cross-tab compare-and-swap or protection against non-cooperating writers.
