## Intent and implemented contract

The feature is **not delivered to Bounty Board**. Existing browser-local drafts and disabled report-source writes are unchanged; no endpoint, browser polling, cross-device autosave, source publishing or enablement was added. The standalone `collaborative_engine.py` is an offline, synthetic-data prototype usable through its Python API, requiring Git `merge-file` and SQLite. It never reads or writes the source report itself. The caller supplies an opaque, stable report key and each full source snapshot. A private local SQLite database serializes participating clients that use the **same database**, records accepted/merged and conflicting content, allows retrieving history, and supports conditional restore against an observed current head. Three-way line merging uses Git. An incoming conflict is recorded instead of replacing the current head; both incoming content and the accepted head are retrievable in history. Source observations are merged against the previous observed source revision. A conflict is not automatically resolved.

This prototype is deliberately **not an app feature or a safe publishing protocol**. Report key construction, root identity, authorization, origin checks, API privacy, bounded polling, local recovery on request/transaction failure, durable unresolved-conflict state and UI conflict resolution must be designed and tested before any integration. Re-observing an unchanged source returns `unchanged`, even if a prior observation conflicted; the caller must inspect history. Conflict resolution and idempotent client request retry are not implemented. Database corruption, write interruption, storage exhaustion, malicious local replacement, history growth/retention, lock contention, abnormal Git exits, source changes during observation and process crashes remain insufficiently tested. Git merge failures/size failures roll back the transaction; a caller must keep its unsaved text. SQLite data and temporary merge inputs can contain sensitive report content; private permissions are not a sandbox or encryption. Do not put this database under an untrusted/shared/synced directory.

## Blockers and guarantees

1. **Source-save safety:** plain filesystem hash check plus rename is not an atomic compare-and-swap against editors, BBH or sync clients. SQLite only serializes clients of one store, and cannot preserve a source update that was overwritten before being observed. The local Shared Syncthing configuration was previously reported as `maxConflicts=0`; remote verification was blocked by lifecycle policy and was not retried or bypassed. Do not claim remote conflict retention or lost-write prevention. Integrating actual source writes needs an owner-approved contract: either cooperation by all writers through a shared conditional-write/lock authority or explicit risk acceptance plus independently durable recovery for every observed version, with the pre-observation gap clearly disclosed. The current prototype provides neither safe source publication nor a basis to enable it.
2. **Missing application path:** build and test report-identity-scoped, host/origin-protected draft API and UI with request idempotency, restart recovery, bounded polling, offline/retry behavior, readable multiple conflicts and a safe undo flow. Prevent responses or errors from leaking unrelated paths/content. Explicitly test multiple browsers/devices against a disposable server and source, external writer races, failure/crash paths and security checks. Current process-client test is not a substitute. Test command for prototype: `PYTHONPATH="$PWD" python3 -W error::ResourceWarning -m unittest discover -s tests -p test_collaborative_engine.py -v`; the browser baseline command above must first be diagnosed.
3. **Prototype risks to resolve:** durable unresolved conflict tracking; requests failing before commit and lost acknowledgements; source deletion/rename; root and report identity; SQLite/merge limits and concurrency/fault injection; privacy/retention; choosing whether Git line merge provides acceptable text granularity. A merge can be semantically wrong even when line-clean. Until reviewed and connected, use only disposable synthetic fixtures.
