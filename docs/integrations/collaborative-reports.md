## Contract and operation

The Bounty Board app now has an **opt-in shared draft** path. Start an isolated server with `--root <synthetic-root> --collaboration-dir <owner-only-private-dir>`; use a Git executable for line-based three-way merging. `--collaboration-dir` is required; without it the collaboration API is disabled and the existing browser-only editor remains unchanged. Store the private database outside the source tree and synced/shared locations. It contains full sensitive report text; owner-only directory/database modes are checked, but this is neither encryption nor a sandbox. It has no retention policy.

The app observes the source on each collaborative request, preserves source/client versions in SQLite, serializes cooperating servers sharing the same private-store lock through observation and database submission, and merges nonoverlapping line edits. This lock requires a trusted, stable private-store directory and a local filesystem providing reliable `flock`; it does not coordinate external editors, sync, or different stores. A conflict is retained, shown in history (including unresolved conflicts older than the latest 100 events), and can be resolved explicitly against the observed head. Resolution and request IDs are persisted transactionally. The UI polls every two seconds, autosaves a shared draft after edits, keeps tab-scoped local recovery, retries failed requests, doesn't replace edits typed while a request is in flight, and offers historical input/result selection as a new shared revision. Browser storage failure remains visible and requires copying the text. Existing browser-only drafts are not silently migrated into the collaborative namespace.

Shared draft save **does not save the report file**. A separate manual publisher is exposed only when `--experimental-fixture-publish` is explicitly specified alongside `--collaboration-dir`, an explicit `TMPDIR`, and a root resolving beneath that `TMPDIR`. This is a synthetic-fixture convenience, **not a security boundary**: an operator controls TMPDIR, and the option must never be used for real reports or the real service. It checks the expected head, refuses unresolved conflicts, observes and rechecks the source, uses a no-follow directory walk and same-directory replace, then observes the result. Local changes observed between the two source reads are recorded and block publication. A writer between the final read and replace can still be overwritten before observation. The private-store lock does not coordinate non-cooperating editors, BBH, Syncthing, independent stores, or other hosts. It does not protect or retain unobserved variants. Do not claim compare-and-swap, cross-host safety, or Syncthing conflict retention.

The API reuses the app's exact Host/Origin and Sec-Fetch-Site restrictions; POST additionally requires a single JSON content type, same origin, and `X-Requested-With: Bounty-Board`. These checks are not authentication against local processes or a replacement for authorized Tailscale Serve. Every collaboration request binds the root identity advertised by `/api/data`; a mismatched root is rejected before observation or write. The identity advertised by `/api/data` hashes the canonical root path; independently, the private store binds that path to its device and inode and refuses a detected replacement, both during requests and on restart. A pre-binding store with existing documents is refused rather than silently mixed; preserve that store and use a new one for isolated tests. Device/inode identity is not a permanent generation ID: inode reuse, filesystem replacement, and rename/replacement races require further review. Report identities are validated and source paths opened without following path-component symlinks. Source deletion/unavailability stops collaboration requests rather than inventing an empty source. History polling returns recent 100 events plus all unresolved conflicts; retained older resolved history is not yet paginated through the API. History/unresolved-conflict growth and storage limits are not bounded. Git's clean line merge can still be semantically wrong.

## Incomplete repair checkpoint

This is **not** a reviewable finished candidate and must not be integrated or activated. The parent owns independent full-diff review after the remaining blockers are fixed.

- Added a process-shared advisory lock spanning source read and database submission for cooperating servers using the same trusted private store. A real two-server-process synthetic HTTP regression holds the first process after its source read, verifies the lock is held using a nonblocking lock probe, waits for the second process at its lock boundary, and asserts the newer source is observed after release. This is not protection from external source writers or store/lock replacement. The private directory is checked for owner-only permissions but its parent is not pinned or guaranteed trusted; replacement could split locks or redirect SQLite. Use only a trusted, stable parent until a separately tested fix exists.
- Added a source-root device/inode binding, refusing detected same-path replacements while running and at restart. Existing unbound history is retained but rejected. Device/inode reuse and replacement between validation and read are not resolved, so this does not satisfy a durable directory-generation guarantee yet.
- A collaborative local draft is no longer marked conflicted merely because its shared revision differs from the source revision; a real browser regression restores and retries an unsent draft after reload with a divergent shared/source base.
- Equal shared acknowledgments and polls no longer replace editor text. Changed shared content uses a minimal CodeMirror replacement so selections outside the change and the existing undo stack survive where possible. Browser tests cover identical acknowledgment/poll plus a remote append away from the cursor; they do not establish all overlapping-selection/undo semantics.
- History still returns full snapshots and unlimited unresolved conflicts; there are no history pagination, version-on-demand, per-operation or database growth limits. Concurrent conflict resolution can strand another editor on a resolved conflict. `window.name` can be inherited by independently opened tabs. Retries remain unbounded and idempotency payloads do not survive reload. These are known blockers, not accepted limitations.
- Fixture publishing remains unsafe against the final-check/replace race and must never be enabled for real reports or sync.
