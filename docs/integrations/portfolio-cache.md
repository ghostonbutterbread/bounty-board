## Intent and observed motivation

These are parent-provided observations, not reproduced here. The change aims to make the browser responsive while discovery waits; it does not make disk discovery faster.

## Contract

One in-memory snapshot and at most one filesystem-discovery worker per server instance. Initial GET starts discovery and returns 202/loading without fabricated programs; completed responses retain the existing data and warnings plus `portfolio` status/timestamp/error. A refresh request uses `X-Portfolio-Refresh: 1`, starts or joins a scan, and retains the last snapshot during a refresh or an exception/incomplete top-level discovery. Metadata write attempts invalidate via a generation counter; a scan started before the attempt cannot publish, and a successor scan starts after it exits. Current capability flags are not cached. The UI uses capped polling, displays status, timestamp and failure, avoids replacing a confirmed metadata update with a stale in-flight response, and prevents new report opens/metadata updates against an unverified replacement source. Report responses already in flight across a manual refresh are discarded. See `BACKEND_API.md` for breaking API contract and `static/API_NEEDS.md` for client behavior.
